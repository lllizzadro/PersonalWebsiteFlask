# Personal Website — Flask (Python)

Louis Lizzadro's personal site — a standalone Flask app, **live at https://louislizzadro.com**. (Built to learn web dev; a retired Go/Gin twin is archived — work only here.)

## Working with Louis

## Stack & conventions
- **Flask + Jinja**, templates in `templates/`; `base.html` is the layout (`{% extends "base.html" %}` + `{% block content %}`).
- **Tailwind via CDN** — no build step; `tailwind.config` inline in `base.html`'s `<head>`. Bespoke CSS (things utilities do poorly: background layer, `.premium-glass`, nav underline, heading font) lives in `static/css/style.css`, linked via `url_for`. Still no-build; if outgrown, next step is a Tailwind build (PostCSS) for purge/`@apply`, not hand-CSS.
- **SQLite** (stdlib `sqlite3`): `get_db()` opens lazily per request, stores the connection on Flask `g`, sets `row_factory = sqlite3.Row`; `@app.teardown_appcontext` (`close_db`) closes it — no per-route close. Path = `os.environ.get('DATABASE_PATH', 'guestbook.db')`. `init_db()` runs at module level with its **own** `sqlite3.connect` (no app context outside a request) — module-level so it works under gunicorn too.
- **Always parameterize queries** (`?` placeholders) — never string-format user input.
- **Secrets via env**: `SECRET_KEY = os.environ.get('SECRET_KEY', 'dev')` signs the session cookie / `flash()`. `'dev'` is local-only; prod sets a real key via Fly secrets.
- **POST/Redirect/GET** for state-changing forms. `add_message()` validates server-side (strip, reject empty, name ≤ 50 / message ≤ 1000), reports failures with `flash()` + redirect; `base.html` renders flashes above `{% block content %}` as a styled red alert (Tailwind utilities).
- **CSRF + spam**: `CSRFProtect(app)` (Flask-WTF) guards all POSTs — forms need `{{ csrf_token() }}` (**parens required**, or you render the function not the token → every POST 400s); reuses `SECRET_KEY`. Guestbook also has an off-screen **honeypot** field (`website`) → silently dropped if filled. Links allowed (Jinja autoescapes; messages render as plain text).
- **Admin auth** (`/admin`, `/admin/login`, `/admin/logout`): single-admin, session-based. `admin_login` compares the POSTed password to `ADMIN_PASSWORD_HASH` (a werkzeug `generate_password_hash` string, via env / Fly secret) with `check_password_hash`, then sets `session['admin']=True` (signed by `SECRET_KEY`). `@admin_required` (`@wraps` + `session.get('admin')` → redirect to `admin_login`) guards protected routes; logout is **POST-only + CSRF + `@admin_required`** (a GET logout would be CSRF-able / link-prefetchable). **Fail-closed**: `ADMIN_PASSWORD_HASH` has **no default** — unset ⇒ every login fails (the `if ADMIN_PASSWORD_HASH and …` guard short-circuits). Don't give it a `'dev'` fallback like `SECRET_KEY`: a plain string isn't a valid hash, so it's both unusable *and* neuters that guard. Cookie hardening: `SESSION_COOKIE_SAMESITE='Lax'` + **`SESSION_COOKIE_SECURE = app.secret_key != 'dev'`** (must stay below the `app.secret_key =` line) — `Secure` is **prod-only** because it's HTTPS-only; hardcoding `True` silently breaks login over local/LAN HTTP (cookie never stored → `/admin` bounces back to login). Templates: `admin_login.html` (password form) + `admin.html` (dashboard — currently just a logout button). Minting the hash: prompt via `getpass` (keeps the password out of shell history / `ps`, and dodges `!` history-expansion); the hash contains `$`, so **single-quote** it when setting the env var.
- **Behind Fly's proxy**: `ProxyFix(app.wsgi_app, x_for=1, x_proto=1, x_host=1)` — Fly terminates TLS and forwards over http, so without it Flask emits `http://` URLs (`_external=True`, `request.base_url`), breaking OG/canonical; with it they're `https://`.
- **Canonical host**: `SITE_URL = 'https://louislizzadro.com'` (in `app.py`, exposed to templates via a context processor). A `@app.before_request` 301-redirects `www.louislizzadro.com` + the legacy `lllizzadro.fly.dev` → the apex (localhost left alone) so there's one canonical host. `base.html` sets `<link rel="canonical" href="{{ SITE_URL }}{{ request.path }}">`; `/robots.txt` + `/sitemap.xml` are Flask routes built from `SITE_URL`.
- **Security headers** (`@app.after_request`): `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/mic/geo off), HSTS (1yr). CSP intentionally omitted (fights the Tailwind CDN + inline scripts — revisit if moving to a build).
- **`<head>` SEO** (`base.html`): per-page `{% block meta_description %}`; OG + Twitter tags reusing `{{ self.title() }}` / `{{ self.meta_description() }}` / `{{ request.base_url }}`; `og:image` → `static/og-image.jpg` (1200×630); **JSON-LD `Person` schema** (schema.org — name/jobTitle/url/address + `sameAs` GitHub+LinkedIn, which ties the domain to his identity for name searches). **Favicons** — three formats in `static/`, all declared via `<link rel="icon">` in `base.html`: `favicon.svg` (`</>` drawn as strokes, font-independent — used by browsers) + `favicon-96x96.png` + `favicon.ico` (raster fallbacks for **Google Search**, which renders a generic globe for SVG-*only* favicons — it wants a square raster, ideally a multiple of 48px; the raster pair was generated from the SVG via realfavicongenerator.net). Google refreshes result favicons slowly (days–weeks) — nudge with Search Console → Request Indexing. No CSP, so inline JSON-LD + the Cloudflare analytics beacon load freely (a future CSP would need to allow them).
- **Errors**: `@app.errorhandler(404)` → `render_template('404.html'), 404` (themed, extends base; the `, 404` keeps the status). A template alone does nothing without the registered handler.
- **Client JS** in `static/js/` via `url_for`: `localtime.js` (local timestamps), `nav.js` (mobile menu), `reveal.js` (scroll-reveal).

## Theming & UI
- **Accent** `purple-600`; **gray base** `neutral` (not `slate` — too blue under purple). Page-title `h1`s are `purple-600` (exception: home hero `h1` is `neutral-100` with only "Louis." in `purple-600`).
- **Fonts**: Inter (body) + Space Mono (headings/brand/nav), via Google Fonts. `tailwind.config` sets `sans`=Inter, `mono`=Space Mono; an `h1,h2,h3` rule in `style.css` applies Space Mono; brand + nav use `font-mono`.
- **Dark-only** — renders dark unconditionally: no theme toggle, no `darkMode` config, no `dark:` variants (all flattened to defaults like `bg-neutral-900`). To re-add light mode: reinstate `darkMode:'class'` + `dark:` variants.
- **Glass UI — two treatments:** (a) **bars & form inputs**: light utility glass `bg-white/5 backdrop-blur-sm backdrop-saturate-150 border border-white/20` (nav `border-b`, footer `border-t`). (b) **panels & cards** (project/guestbook cards, résumé sheet): the **`.premium-glass`** class in `style.css` — near-black translucent base + white→purple highlight gradient + inset top-highlight + drop shadow + low blur + a `::before` purple edge sheen; `.premium-glass > *` lifts content above the sheen; add **`.interactive`** for hover lift. Hard-won rules: (1) background lives **only on `body`** — panels are translucent so it shows through; never repeat it on `nav`/`section` (each re-anchors → muddy). (2) `backdrop-saturate` is essential — plain blur desaturates/looks muted; saturate re-pops color. Dials: blur=frostiness, fill opacity=clarity, border=edge. (3) **don't double-layer** — the mobile menu is *inside* `nav`, so it has no bg of its own.
- **Background** (`style.css`): cosmic image `static/images/purpleCosmic.jpg` on a **`body::before` fixed layer** (`position:fixed; top/left:0; width:100%; height:100lvh` w/ `100vh` fallback; `z-index:-1; background-size:cover`), `#080911` base/fallback. Referenced with a relative `url(../images/...)` (external CSS resolves URLs to itself). Commented purple `radial-gradient` glow layers sit there for optional re-enable. **Mobile gotchas (don't regress):** `background-attachment: fixed` is buggy on mobile → use the fixed pseudo-element instead; size with **`100lvh`** not `100vh`/`inset:0` (the address bar showing/hiding changes viewport height and makes a `100vh` layer **jump mid-scroll**). **Optimize images** — PNG → JPEG/WebP (`sips -s format jpeg -s formatOptions 82` took 1.6 MB → 176 KB); never ship big PNGs for photographic art. A slow `nebula-pan` keyframe (transform scale/translate, ~20s, reduced-motion-gated) drifts the image subtly — cheap GPU transform, but it re-blurs the glass each frame, so keep it slow/subtle.
- **Per-page content width**: `base.html` defines `{% block main_width %}max-w-3xl{% endblock %}` once (nav container) and reuses it on `<main>` + footer via `{{ self.main_width() }}` (a block can only be *defined* once; `self.` re-renders it). Home overrides to `max-w-5xl` (two-column hero); others default `max-w-3xl`. Keeps nav/content/footer edges aligned.
- **Nav** (`base.html`): brand is `</>` glyph + name. Inline links on `md+` (`hidden md:flex`); hamburger (`#nav-toggle`, `md:hidden`) opens the in-flow `#mobile-menu` — `nav.js` toggles `.open`, which animates `max-height` + `opacity` + `padding` in `style.css` (NOT `display:none` — can't transition). Collapsed = `max-height:0` **with padding zeroed** (padding can't compress under `max-height`, so it lives in `.open` to avoid a leftover gap). Active page: `aria-current="page"` (Jinja exact `==`) → CSS colors it (`nav a[aria-current="page"]`) and desktop `.nav-link`s get a center-out sliding underline (`::after`, also on `:hover`); mobile links get the color only.
- **Timestamps**: stored UTC, shown local — `<time>` carries ISO-UTC `datetime` (`| isodate`) with `| prettydate` fallback; `localtime.js` rewrites via `toLocaleString`.
- **Scroll-reveal**: `.reveal` elements fade/rise via `reveal.js` (IntersectionObserver adds `.is-visible`, then unobserves — reveal once). An inline `<head>` script adds a `js` class to `<html>` so the hidden state (`.js .reveal{opacity:0}`) only applies with JS — no-JS users still see content. Bounded `:nth-child(3n+…)` stagger so scroll-triggered cards don't lag; reduced-motion shows immediately. Applied to project + guestbook cards (not the above-fold hero).
- **Focus**: global `:focus-visible { outline: 2px solid purple-600; outline-offset: 2px }` for keyboard users. Don't set `border-radius` there — modern outlines already follow each element's own radius, and forcing it squares rounded elements on focus.

## Deployment — Fly.io (live)
- **App `lllizzadro`** → origin at https://lllizzadro.fly.dev (region `ord`). Docker (`python:3.13-slim`, gunicorn `:8080`) + `fly.toml` + `.dockerignore`.
- **Custom domain** (live): `louislizzadro.com` (+ `www`), registered at **Cloudflare** and **proxied** (orange-cloud, SSL/TLS **Full (strict)**) in front of Fly → DDoS + hidden origin IP. Certs issued via `fly certs add`; Cloudflare DNS A/AAAA point at Fly. `www` + the bare `fly.dev` 301 → apex (see Stack & conventions). When proxied, real client IP is in `CF-Connecting-IP` (matters for *app-level* rate-limiting; the edge rule below keys on the true client IP automatically). Fly's cert auto-renews through the proxy; if a renewal ever fails, grey-cloud temporarily → renew → re-proxy.
- **Analytics**: **Cloudflare Web Analytics** (cookieless, privacy-friendly) — enabled via automatic edge injection since the site is proxied, so there's **no snippet in the code**. View in the Cloudflare dashboard.
- **Rate limiting** (admin brute-force): a **Cloudflare edge rate-limiting rule** (`admin-login-throttle` — the free plan's one allowed rule) throttles the login at **>5 req/min per IP → Block 10 min**. Lives **only in the Cloudflare dashboard** (Security → Rate limiting rules), **not in git** — like Web Analytics, it's silent config drift, hence this note. Matches **path-only** (`http.request.uri.path eq "/admin/login"`) because the free-tier rule builder doesn't expose Request Method (typing `method` → "No options") — fine, since nobody legitimately GETs the login page in bulk and a flood looks the same GET or POST. Runs at the **edge**, so it caps a flood *before* it reaches Fly — protecting the origin CPU from `scrypt`-hash flooding (the real value; a strong hashed password already makes online brute force infeasible). App-level Flask-Limiter left deferred as a learning exercise only; it'd have to key on `CF-Connecting-IP` since `ProxyFix(x_for=1)` unwinds only one of the two proxy hops (Cloudflare → Fly).
- **Persistent SQLite**: 1 GB volume `data` at `/data`; `DATABASE_PATH=/data/guestbook.db` survives redeploys. **Single machine only** — a volume binds to one machine; scaling out diverges the data.
- **CI/CD** (`.github/workflows/fly-deploy.yml`): deploys on **push to `main`**. Flow: work on `dev` → PR → merge to `main` = production. Needs the `FLY_API_TOKEN` Actions secret (`fly tokens create deploy`).
- **Fly secrets**: `SECRET_KEY` (session signing) + `ADMIN_PASSWORD_HASH` (admin login) via `fly secrets set`. **Single-quote the hash** — `fly secrets set ADMIN_PASSWORD_HASH='scrypt:…$…$…'` — because its `$` salt/digest segments get shell-expanded otherwise, silently storing a *corrupted* hash so every prod login fails with the right password (double quotes don't help; only single quotes suppress `$`). Setting a secret auto-restarts the machine; the stored value can't be read back (`fly secrets list` shows only a digest), so to fix a bad one just overwrite it. Admin login stays fail-closed (unusable) until `ADMIN_PASSWORD_HASH` is set; `SESSION_COOKIE_SECURE` auto-enables in prod because `SECRET_KEY` is non-`'dev'`.
- **Ops**: `fly status` / `fly logs` / `fly open`; `fly ssh console` (only `/data` persists); `fly ssh sftp` for the DB. Manual deploy needs flyctl (Windows: `iwr https://fly.io/install.ps1 -useb | iex`).

## Decided against
- **Projects → DB CRUD** — once planned (would've taught schema design, migrations, and an update op), **deliberately dropped**. For a solo *technical* author, editing the `PROJECTS` constant in `app.py` and committing is the better design, not the lazy one: changes stay version-controlled + auto-deploy, and the data stays replicated in the repo instead of living on the single Fly volume. The `tech` *list* also fits a Python list far better than a SQLite row (a DB would force a JSON/CSV column or a `project_tech` join table). A DB earns its place for *runtime / other-people* content — that's the guestbook, already built C/R/D. The CRUD/migration learning reps are real but belong on a throwaway project, not bought by compromising the site. (`admin_required` forwarding only `**kwargs` is fine either way — Flask passes URL params as kwargs, as the guestbook-delete route confirmed.)
