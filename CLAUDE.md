## Stack & conventions
- **Flask + Jinja**, templates in `templates/`; `base.html` is the layout (`{% extends "base.html" %}` + `{% block content %}`).
- **Tailwind via CDN** — no build step; `tailwind.config` set inline in `base.html`'s `<head>`. A small **custom-CSS layer** lives in `static/css/style.css` (linked via `url_for`) for what utilities do poorly: the background layer, the `.premium-glass` panel recipe, the nav underline, and the `h1,h2,h3` font rule — still no-build (just a static file). If it ever outgrows the CDN, the next step is a Tailwind **build** (PostCSS/CLI) for purge/`@apply`, not hand-written CSS.
- **SQLite** (stdlib `sqlite3`): `get_db()` opens lazily per request, stores the connection on Flask `g`, sets `row_factory = sqlite3.Row`; a `@app.teardown_appcontext` (`close_db`) closes it — no per-route close. DB path = `os.environ.get('DATABASE_PATH', 'guestbook.db')`. `init_db()` runs at module level with its **own** `sqlite3.connect` (not `get_db()` — there's no app context outside a request); module-level so it also works under gunicorn.
- **Always parameterize queries** (`?` placeholders) — never string-format user input.
- **Secrets via env**: `SECRET_KEY = os.environ.get('SECRET_KEY', 'dev')` signs the session cookie / powers `flash()`. `'dev'` is local-only; prod sets a real key via Fly secrets.
- **POST/Redirect/GET** for state-changing forms. `add_message()` validates server-side (strip, reject empty, name ≤ 50 / message ≤ 1000) and reports failures with `flash()` + redirect; `base.html` renders flashes above `{% block content %}`.
- **Client JS** in `static/js/`, loaded via `url_for('static', ...)`: `localtime.js` (local timestamps), `nav.js` (mobile menu toggle).

## Theming & UI
- **Accent** `purple-600`; **gray base** `neutral` (not `slate` — too blue under purple). Page-title `h1`s are `purple-600` (exception: the home hero `h1` is `neutral-100` with only the accent word "Louis." in `purple-600`, per the mockup).
- **Fonts** (Google Fonts): Inter (body) + Space Mono (headings, brand, nav). `tailwind.config fontFamily` sets `sans`=Inter, `mono`=Space Mono; an `h1,h2,h3` rule in `static/css/style.css` applies Space Mono to headings; brand + nav links use the `font-mono` class.
- **Dark-only theme** (light mode removed 2026-06-17): the site renders dark unconditionally — no theme toggle, no `theme.js`, no `darkMode` config, no inline theme script. All former `dark:` variants were flattened to plain defaults (e.g. `bg-neutral-900`, `text-neutral-400`); cards/panels now use the **glass system** (below), not solid `neutral-800`. (If light mode is ever wanted again, reintroduce `darkMode: 'class'` + the `dark:` variants.)
- **Glass UI** (2026-06-17 redesign, refined 2026-06-18) — **two** treatments: (a) **Bars & form inputs** use light utility glass via Tailwind: `bg-white/5 backdrop-blur-sm backdrop-saturate-150 border border-white/20` (nav `border-b`, footer `border-t`; inputs keep the purple focus ring). (b) **Panels & cards** (project cards, guestbook message cards, résumé sheet) use the **`.premium-glass`** class in `style.css`: near-black translucent base + faint white→purple highlight gradient + `inset` top-highlight + drop shadow + low `backdrop-blur` + a `::before` purple edge sheen. `.premium-glass > *` auto-lifts content above the sheen (no wrapper needed); add **`.interactive`** for the hover lift (`translateY(-3px)` + purple edge glow) — static panels (code window, résumé sheet) omit it. Three principles learned the hard way: (1) the page background lives **only on `body`** — panels are translucent so it shows through; do NOT repeat it on `nav`/`section` (each re-anchors its own copy → muddy). (2) `backdrop-saturate` is essential — plain blur desaturates what's behind it and looks muted; saturate re-pops the color. Dials: blur = frostiness, fill opacity = clarity, border brightness = edge. (3) **Don't double-layer** — the mobile menu sits *inside* `nav` so it has **no** bg of its own (nav's glass shows through), and it's **in-flow** (`border-t`, pushes content down), not an `absolute` overlay (which was unreadable over text).
- **Background**: cosmic image `static/images/purpleCosmic.jpg` painted on a **`body::before` fixed layer** (`position: fixed; top:0; left:0; width:100%; height:100lvh` with a `100vh` fallback; `z-index:-1`; `background-size: cover`), `#080911` as the base/fallback on `body`. Lives in `static/css/style.css`; two purple `radial-gradient` glow layers are kept **commented** there for optional re-enable. **Two mobile gotchas solved here (don't regress):** (1) `background-attachment: fixed` is buggy on mobile (iOS mis-scales/stutters) → use a fixed-positioned pseudo-element instead. (2) sizing it with `inset:0`/`100vh` made it **jump mid-scroll** when the mobile address bar shows/hides (viewport-height change) → `100lvh` (largest viewport height) is constant, so no jump. **Image-path note:** in the external stylesheet the image is a **relative** `url(../images/purpleCosmic.jpg)` (a real `.css` resolves URLs relative to itself — `/static/css/` → `/static/images/`); the old *inline* `<style>` couldn't do that and needed Jinja `url_for`. **Optimize images** — source was a 1.6 MB PNG → 176 KB JPEG via `sips -s format jpeg -s formatOptions 82` (~90% smaller, no visible loss); prefer JPEG/WebP over PNG for photographic/gradient art.
- **Per-page content width**: `base.html` defines `{% block main_width %}max-w-3xl{% endblock %}` once (on the nav container) and reuses its value on `<main>` and the footer via `{{ self.main_width() }}` (Jinja renders a block's value in multiple spots this way — a block name can only be *defined* once). A page sets its width with one line: the home page overrides to `max-w-5xl` (wider, for the two-column hero); other pages default to `max-w-3xl`. Keeps nav / content / footer edges aligned per page.
- **Nav** (`base.html`): brand is a `</>` glyph (`<span class="text-purple-600">&lt;/&gt;</span>`) + name. Responsive — inline links on `md+` (`hidden md:flex`); a hamburger (`#nav-toggle`, `md:hidden`) opens the in-flow `#mobile-menu` (`nav.js` toggles `hidden`). Active page is marked with `aria-current="page"` (Jinja `{% if request.path == '/...' %}`, exact `==` — `in`/`startswith` would mis-highlight); CSS colors it (`nav a[aria-current="page"]`) and desktop links (`.nav-link`) get a center-out sliding underline (`::after`, also on `:hover`). Mobile links get the active color only.
- **Timestamps**: stored UTC, shown in each visitor's local time — `<time>` carries an ISO-UTC `datetime` (`| isodate` filter) with a `| prettydate` fallback; `localtime.js` rewrites it via `toLocaleString`.

## Run
```
pip install -r requirements.txt
python app.py        # http://localhost:5000
```
LAN testing (view on phone): `python -m flask --app app run --host=0.0.0.0 --port=5000` → `http://<computer-LAN-IP>:5000`.

## Deployment — Fly.io (live)
- **App `lllizzadro`** → https://lllizzadro.fly.dev (region `ord`). Docker (`python:3.13-slim`, gunicorn on `:8080`) + `fly.toml` + `.dockerignore`.
- **Persistent SQLite**: 1 GB volume `data` mounted at `/data`; `DATABASE_PATH=/data/guestbook.db` keeps data across redeploys. **Single machine only** — a volume binds to one machine; scaling out would diverge the SQLite data.
- **CI/CD**: `.github/workflows/fly-deploy.yml` deploys on **push to `main`**. Flow: work on `dev` → PR → **merge to `main` = production**. Requires the `FLY_API_TOKEN` GitHub Actions secret (created via `fly tokens create deploy`).
- **Ops**: `fly status` / `fly logs` / `fly open`; `fly ssh console` (only `/data` persists); `fly ssh sftp` to pull/push the DB. Manual deploy needs flyctl (Windows install: `iwr https://fly.io/install.ps1 -useb | iex`).
